# Unused Codebase Cleanup Plan

Status: Completed

## Audit Scope

Audited tracked files, Go imports/usages, application composition in `cmd/main.go`, tests, README/HANDOFF references, and ignored runtime artifacts.

## Findings

### Safe to Remove

#### `internal/core/ports/whatsapp_client.go`

Evidence:

- The `WhatsAppClient` interface is only referenced by the compile-time assertion in `internal/adapters/whatsmeow/client.go`.
- `cmd/main.go` uses the concrete `*whatsmeow.Client` adapter directly for `Connect`, `Disconnect`, and `AddEventHandler`.
- No service, handler, test, or composition code depends on the port.
- The adapter's outbound behavior is exposed through `ports.MessageSender`, not `ports.WhatsAppClient`.

Removal steps:

- Delete `internal/core/ports/whatsapp_client.go`.
- Remove `var _ ports.WhatsAppClient = (*Client)(nil)` from `internal/adapters/whatsmeow/client.go`.
- Run formatting, tests, and vet.

### Dead Code to Remove, Not Whole Files

#### `Config.LogLevel` and `LOG_LEVEL`

Evidence:

- `Config.LogLevel` is populated by `config.Load` but has no runtime consumer.
- `LOG_LEVEL` is not documented as an active behavior and no logger uses it.

Removal steps:

- Remove the `LogLevel` field from `Config`.
- Stop loading `LOG_LEVEL`.
- Remove any documentation that presents `LOG_LEVEL` as supported, if found.
- Run tests and vet.

### Local Runtime Artifact

#### `whatsmeow.db`

Evidence:

- It is ignored by `.gitignore` and is not tracked by Git.
- It is generated by the local SQLite WhatsMeow store at runtime.
- It is not source code or a required repository asset.

Removal steps:

- Delete the local file only after confirming the current WhatsApp session is disposable.
- Do not add it to Git or commit it.
- Keep the existing `*.db` ignore rule.

## Keep

- `.opencode/plans/*.md`: active/historical implementation plans referenced by HANDOFF.
- `services/worker/docs/api-mapping-webhook.md`: source mapping specification referenced by the project documentation.
- All `*_test.go` files: each is exercised by `go test ./...` and protects inbound, outbound, HTTP, and dispatcher behavior.
- `internal/core/domain/outbound.go` optional request fields: they represent the WABA request envelope even when the current text mapper does not yet implement every field.
- `internal/core/ports/message_sender.go`: used by the outbound service and WhatsMeow adapter.

## Implementation Order

1. Remove the unused `WhatsAppClient` port and its assertion.
2. Remove the unused `LogLevel` configuration field and environment lookup.
3. Decide whether to remove the local `whatsmeow.db` session artifact.
4. Run `gofmt -w <changed-go-files>`.
5. Run `go test ./...`, `go test -race ./...`, and `go vet ./...`.
6. Run `git diff --check` and inspect the final status.
7. Update `HANDOFF.md` with removed files/dead configuration and verification results.

## Acceptance Criteria

- No references to `ports.WhatsAppClient` remain.
- No references to `Config.LogLevel` or `LOG_LEVEL` remain.
- Application composition and runtime behavior are unchanged.
- Existing Direct Send and webhook tests remain green.
- No tracked database, credential, or generated artifact is introduced.
